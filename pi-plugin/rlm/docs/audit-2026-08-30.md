**Date:** 2026-08-30 · **Scope:** `rlm.pi` plugin (`pi-plugin/rlm/src/`) + artifacts in

## 0. Answers to the three reported symptoms (TL;DR)

| Symptom | Verdict |
|---|---|
| "rlm_query / llm_query sometimes fail — why?" | Multi-cause: provider transients (idle timeout on fat contexts, 429/1302), context-overflow 400s, prompt-size caps, per-turn budget granularity overshoot. Full taxonomy in §1. **Failures are invisible in `.rlm` artifacts by design** — episodes are success-only (§4.1), which is why the logs look clean. |
| "rlm agents think forever and never call llm_query — is that fine?" | Legal-by-design: a child RLM may spend all 30 turns on free `repl` work (search/grep); only advisory nudges exist, nothing forces a sub-call (`core/iteration.ts` has no gate). BUT when they run out of turns the finalize path is broken (§2) and returns garbage. |
| "grok-4.6 is 500k max — how can a node show 524.1k tok?" | That number is **cumulative Σ `usage.totalTokens` over the node's own turn completions**, not the context size. Each turn re-sends input well under the window; the sum across ~30 turns is unbounded by the window. It also includes `cacheRead`/`cacheWrite`, which the budget accounting (input+output only) does not count — so display > budget > window is expected. Context-per-turn is guarded by compaction (65% threshold) + budget (§5.1). Not a bug, but a display/labeling problem (§6, F5). |

## 1. Why `rlm_query` / `llm_query` fail — full taxonomy

### 1.1 Leaf calls (`llm_query` / `llm_batch`) — fail SOFT, Python gets `Error: …` strings
`complete1` "never throws" (`bridge/handlers/completion.ts:30-31`); soft failures return
`formatError(msg)` = `"Error: …"` as the task result. Paths:

| # | Cause | Where | What Python sees |
|---|---|---|---|
| L1 | Prompt too big | `completion.ts:44-48`, cap `maxPromptChars=400_000` (defaults.ts:33) | `Error: sub-LLM prompt exceeded the size limit (N chars > max). Shorten or chunk the prompt…` |
| L2 | Sub-call resource timeout | `core/resource-limits.ts:10` | `Error: timeout exhausted` |
| L3 | Provider error after retries exhausted | `bridge/model.ts:107-108` throws → `util/retry.ts:159-173` → `completion.ts:70-75` | `Error: <provider msg>` (+ ` — try smaller batches or individual llm_query calls` when `/credit|402|quota|rate.limit/i`) |
| L4 | Bridge unwired | `llm-query.ts:16,87-96,135-144` | `Error: RLM bridge not wired for this invocation` + SPAWN_HINT |
| L5 | Duplicate in-flight call | echo stub `ledger.ts:141`, coalesce `rlm-query.ts:172-177` | stub / twin's result — by design, not a failure |
| L6 | **One hard throw rejects the WHOLE batch** | `Promise.all` in batch path → `task-registry.ts:193-195` | all ~20 batch items lost because 1 item's provider call hard-failed |

Retry policy (`util/retry.ts`): 3 attempts (`retryMaxAttempts`), 500ms→15s backoff;
429 parks on shared per-provider cooldown up to 8 windows (`rateLimitMaxAttempts`), 2s→60s.
Non-retryable: 400/401/402/403/404/413/422 or text matching `context length|too large|invalid request|…`.
Retryable text includes `upstream|timeout|429|1302|速率|频率` — the logged
**`Error: Upstream idle timeout exceeded`** (sollab ep @2026-08-27, glm-5.3) is provider-side
(changelog 0.3.x already noted "glm-5.3 dying to idle timeout on fat contexts").

### 1.2 Child RLM runs (`rlm_query`) — fail HARD, parent gets one error string
`bridge/handlers/rlm-query.ts:211-215`: catch → `ledger.fail` + node status `error` →
`emptyResult(formatError("child RLM failed - " + msg))`. The inner engine rethrows any completion
error that is not `LimitError`/abort (`core/engine.ts:467-476`) — there is **no turn-level retry**:
one unlucky provider failure after `completeWithRetry` gives up kills a run that may already have
spent 300k+ tokens.

Escalation causes inside a child run:
- **C1** provider transients (above) — 3 tries then dead.
- **C2** context-overflow 400 → NON_RETRYABLE → instant death. Guard is compaction
  (`shouldCompact`, threshold 65% of window, defaults.ts:36) — there is **no preflight estimate
  before `complete`**, so a turn that jumps past the window between compactions 400s.
- **C3** `LimitError`: `maxTimeoutMs` wall clock, `maxTokens`, `maxErrors=5` consecutive REPL
  errors (`core/limits.ts:73-91`) → returns "best partial" (see §2 for why that can be garbage).
- **C4** depth/gates: `maxDepth=4`, `maxConcurrentChildren=4`, `rlmBudget=8` → rejected spawns.
- **C5** `requestTimeoutMs=15min` per completion (defaults.ts:9) — long grok thinking can hit it.

### 1.3 Budget overshoot — the 6.7M-token episode
`TokenBudget.observeTotal` is called **once per turn** (`engine.ts:412-414`). Within one turn the
child can fan out unbounded leaf volume (session gate is only `maxConcurrentSubcalls=8` × 15min).
Evidence: sollab episode @2026-08-25, glm-5.2, **tokensIn=6,747,276** — vs. cap
`min(0.25×1M, 400k)=250k` × 3 windows = 750k "bounded" chain total. ~9× overshoot. The budget is
real but its granularity is per-turn; intra-turn fan-out is unbounded.

## 2. THE garbage-answer bug (fence bug) — root cause + live evidence

**Mechanism (3 holes, one family):**
1. `FINALIZE_PROMPT` (`prompts/user.ts:25-28`) literally instructs: *set `answer["content"]` …
   "(fenced ```repl```)"*. When turns run out, `finalize()` (`engine.ts:518-532`) completes and
   returns `text.trim()` — **the raw fenced ```repl block, never executed, never stripped** —
   and that becomes the official answer (`persistRoot`).
2. `best`-partial on abort/`LimitError` (`engine.ts:466-474`): `else if (!best && turn.response.trim())
   best = turn.response;` — if the model never set `answer["content"]`, `best` is the **first
   turn's raw response** (which naturally contains ```repl fences), frozen for the whole run.
3. Python side: `finalAnswerOf`/`latestAnswerContentOf` (`core/answer.ts`) accept whatever the
   model put in `answer["content"]` — including a literal fence block — with zero validation.

**Then it poisons the replay cache:** success-path `recordEpisode` (`rlm-query.ts:193-203`) stores
`res.answer` unconditionally; `memory.replay(key)` (`rlm-query.ts` ~line 135) returns
`hit.result` verbatim for identical `taskKey` = sha256(kind|model|pathSig|normalizedPrompt|ctxSig)
(`core/ledger.ts:130-138`). Garbage is replayed forever.

**Evidence:**
- Historical: **45/468 episodes (9.6%)** have a result starting with a code fence; 4 more are
  trivial (`'...'`, `'done'`, `'assembled'`). One specimen contains the model's own comment:
  `# The llm_batch was just spawned and not awaited; but we are out of turns.` → returned as the answer.
- **Live: 4 of 8 sub-RLM studies fired during this investigation returned their own ```repl
  scripts as the final answer** (turn-limit → finalize → fence). 50% failure rate on
  study-style tasks against this very repo.

**Why children "spin without llm_query":** `core/iteration.ts:41-67` executes whatever repl blocks
arrive; there is no rule forcing sub-calls. Nudges are advisory only (system prompt red-flag
"two turns with zero sub-LLM calls"; `WRAP_UP_BUDGET` at 80% budget; `Turn N/30` prefixes).
With `maxIterations=30` and heavy free searching, study-tasks exhaust turns → finalize → fence.

## 3. Token display semantics (the "524k > 500k" question)

- Row value: `tree-rows.ts:32-34` prints `row.tokens + model`. Accumulated at
  `tool/subcall-store.ts:74-76` (`sc.tokens += event.tokens`, never reset).
- Who emits: for an **rlm_query node**, the child engine in self-report mode emits per turn
  (`engine.ts:406-407`): `tokens: turn.usage.totalTokens`. `childRun`'s completion emit sends NO
  tokens (`rlm-query.ts:205-209`). Leaf children are separate rows, NOT rolled into the parent.
- ⇒ Node number = **Σ over that node's own turn completions** of `usage.totalTokens`.
  pi-ai `Usage` (`node_modules/@earendil-works/pi-ai/dist/types.d.ts:189-196`) has separate
  `input`, `output`, `cacheRead`, `cacheWrite`, `totalTokens`.
- Budget accounting (`core/limits.ts:44-47` `addUsage`) sums `usage.input + usage.output` only.
  So on a caching provider (xai), display (incl. cacheRead) can legitimately read 524k while
  budget accounting stays under cap `min(0.25×500k, 400k)=125k`, chain ≤375k.
- Per-turn context size is separately guarded by compaction (65% of window) — the window itself
  is not exceeded by a turn; the counter is just cumulative.

## 4. Diagnosability problems (why `.rlm` looks clean while things fail)

1. **Failed calls are never recorded.** `memory.ts:192` skips empty results; the child error path
   (`rlm-query.ts:211-215`) writes no episode; `persistRoot` is success-only (`engine.ts:399,452,462`).
2. **`llm_query`/`llm_batch` never write episodes at all** (only kinds `rlm` and `root` exist,
   `memory.ts:27-38`; `llm-query.ts` has zero `recordEpisode` calls).
3. Node `error` status lives only in the in-memory tree; gone after the session.
4. `episodes.jsonl` grows unbounded (4.0MB sollab / 1.2MB zebra-catch), rows carry full
   prompt+result text; no rotation/trim.
5. Replay returns `hit.result` with `iterations:0, cost:0` — indistinguishable from fresh except
   by the `(replay)` label; no freshness/staleness signal.

## 6. Fix plan (ordered, with verification)

### P0 — answer hygiene + cache poisoning (B1–B4)
**F1. Sanitize every answer path.** New `sanitizeAnswer(text)` in `core/answer.ts`:
strip surrounding code fences; reject trivia (`/^(\.|\.\.\.|done|ok|assembled)$/i`, `< N chars`
with no digits/file paths); if the text is (or contains) a ```repl fence, treat it as NOT a final
answer. Apply in: `finalize()` return, `finalAnswerOf` consumer, `best` assignment, abort/LimitError
`result(...)` construction.
**F2. Execute-then-finalize.** In the out-of-turns path, instead of returning raw text: if the
finalize completion contains a fenced block, run it through the existing turn machinery
(`pendingReplOutputs` path) once so `answer["content"]/["ready"]` is honored; only fall back to
plain text if the block errors. (This matches FINALIZE_PROMPT's own instruction — today the block
is never executed.)
**F3. Better `best` tracking.** Update `best` to the LATEST non-empty `turn.response` (not first):
`else best = turn.response.trim() || best`.
**F4. Replay guard.** `memory.replay` / caller: skip hits whose result starts with `Error:` or
fails `sanitizeAnswer`; optionally require `hit.result.length ≥ 200`. Also record and expose
`replayedAt` count.
**Verify:** new test in `pi-plugin/rlm/test/` (phase-style): stub model whose last message is a
fence → run engine → assert answer has no fence and episode row passes sanitizer; identical
second run must NOT replay the junk.

### P1 — resilience (B5–B8)
**F5. Turn-level completion retry.** In the engine loop, catch completion errors:
if `retryableError`-class (transport/idle/429-exhausted) and consecutive completion failures ≤2,
append `"[runtime] completion failed: msg — retrying"` user msg and `continue` (do not count the
turn). Only rethrow after 2 consecutive completion failures. Keep `LimitError`/abort semantics.
**F6. Budget intra-turn observation.** Route leaf/child usage through the budget too: in the
invocation `addUsage`/`addRaw` seams, call `budget.observeTotal` (or a cheap atomic check) so a
turn that fans out past hard-cap stops spawning new leaves (soft note stays per-turn).
**F7. Per-item batch isolation.** llm_batch: wrap each item so one hard throw degrades that item
to `Error: …` string instead of rejecting the whole batch.
**F8. Overflow preflight.** Before `complete`, estimate history tokens (reuse `text/` estimator);
if `est + rootSampling.maxTokens > contextWindow` → force `compactHistory` regardless of the 65%
threshold; if still over, hard-truncate oldest turns.
**Verify:** unit tests for F5 (mock complete that fails once then succeeds), F7 (batch with one
poison item), F6 (fan-out overshoot stops at hard cap).

### P2 — diagnosability + UX (B9–B12, B16)
**F9. Record failures.** Add `kind:"rlm-error"` (or `ok:false` flag) episodes in the childRun
catch path; make `replay` skip them. Optionally sample-record `kind:"llm"` leaves.
**F10. Rotate episodes.** Size- or count-based trim in `appendEpisode` (e.g. keep last 2MB/2000
rows), fail-soft.
**F11. Label the token column.** `tree-rows.ts`: render `Σ524k` (or `in/out` split, or add
`cached` suffix) so nobody reads it as context size; consider surfacing `turn N/30` on the rlm row
(the self-report detail already carries it).
**F12. Window fallback warning.** When `contextWindowOrFallback` falls back to the 32k table
default, emit a one-time warning node/status; refresh built-in table + `models_cache.json`
(grok-4.6=500k already cached correctly in both projects).
**F13. Per-provider retry/payload overrides** in `rlm.json` (e.g. `zai-coding-cn:*: retryMaxAttempts 4`,
smaller elision) to mitigate glm idle-timeout on fat contexts.
**Verify:** run a scripted session that forces a child failure → assert `.rlm` now contains the
error row and replay doesn't return it; eyeball tree label.

### P3 — polish (B13–B16)
F14: observe finalize usage into budget. F15: consider a stronger "wrap up by turn ~25" nudge or
config `maxIterations` bump for study tasks. F16: remove duplicated comment. F17: document the
`Σ tokens` semantics in the status-line tooltip/glossary.
